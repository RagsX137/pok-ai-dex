Agentic Pokédex
Agentic Edition — Dashboard + Coach

A full-stack Pokédex powered by Coveo Atomic for enterprise-grade search, Coveo CRGA for grounded generative answers with citations, and a local Ollama LLM for fully offline inference. Search any Pokémon by name, type, ability, or natural language on the dark 3-column dashboard — or open the Pokémon Coach and hold a real conversation with Professor Oak: he remembers the last few turns, resolves pronouns, renders side-by-side comparison panels on demand, and every answer is graded against an 18×18 type chart before you see it. No build step. Just Flask + Coveo + local inference.

Flask 2.x Coveo Atomic v3 Coveo CRGA Ollama PokéAPI Python 3.11+ Vanilla JS (ESM) pytest + Playwright

Architecture
🔍
Coveo Atomic
Web component search engine. Headless engine proxied through Flask — API keys never reach the browser.
🎓
Coveo CRGA
Relevance Generative Answering (Professor Oak). SSE stream consumed server-side, returned as JSON with citations.
🤖
Ollama (local LLM)
llama3, mistral, gemma3, phi4 — any pulled model. Generates grounded RGA answers from Coveo search context.
🗄️
Flask API
Four blueprints — pages, coach_api, coveo_api, llm_api — wired by create_app().
💬
Conversation Store
In-memory sessions, 20 turns each, 1 000 sessions max with LRU eviction. No persistence — cleared on restart.
⚖️
Answer Grading
Coach answers run through eval_harness.grading — type and chart claims are checked and flagged inline.
🧪
Eval Harness
Repeatable wild-encounter evaluation. Draws scenarios from the live index, grades answers, stores runs in SQLite.
🗺️
PokéAPI + Serebii
Stats, moves, types, and encounter locations from PokéAPI. Region maps sourced from Serebii Pokéarth.
🖼️
PokémonDB Artwork
High-res artwork from pokemondb.net CDN. Sprite fallback in the sidebar lens, comparison cards, and rec grid.
Pokémon Coach — anatomy of a turn
01
Trainer asks
Textarea with live Coveo query suggestions from a hidden Atomic search box.
02
History folded in
Last 4 turns prepended; Oak's replies truncated to 200 chars so the new question still dominates.
03
Intent detected
Four regex patterns spot "X vs Y", "compare X and Y", "between X and Y", "X or Y".
04
CRGA answers
Coveo generates a grounded answer. If the model abstains, the top search excerpts are returned instead.
05
Answer graded
Type and chart claims are checked against the type chart; mismatches come back as flags.
06
Rendered
Bubble with citation pills and ⚠ flags — plus a dual comparison panel when intent was detected.
Conversation Memory
Each browser session gets a UUID. The server keeps the last 20 turns and the canonical Pokémon names mentioned in each, so "who counters it?" resolves correctly even when the original message was misspelled.
Side-by-Side Comparison Panels
Ask "Compare Gyarados and Vaporeon" and the answer bubble is followed by two full stat panels — artwork, base stats, weaknesses, resistances, moves — with a ΔBST delta column between them and a verdict bar naming the higher-BST Pokémon.
Inline Answer Grading
The same grader the eval harness uses runs on every live answer. A wrong type matchup surfaces as a ⚠ Type error flag under the bubble rather than passing silently.
Challenge Mode
The 🎲 chip calls /api/coach-challenge, which draws a real scenario from the eval harness — a team of six and a wild Pokémon on a chosen difficulty axis — and opens the conversation with it.
Deep-linked Comparisons
Hovering a dashboard result reveals a Compare button that opens /coach?compare=X&with=Y — the coach fires the comparison on load.
Name Spell-Correction
When a PokéAPI lookup 404s, the client asks /api/pokemon-correct, which Levenshtein-matches the name against data/pokemon_db.csv within 2 edits and retries once.
Dashboard Features
3-Column Dark Dashboard
Left sidebar (type chips + generation filter + map card), scrollable center column (search, photo, results, similar Pokémon), and a sticky right panel (stats, moves, type effectiveness, AI rec).
Natural Language Search
Ask anything — "fastest fire type", "best water starter", "which Pokémon evolves from Eevee using a fire stone" — powered by Coveo's semantic index with a custom Semantic-PokEncoder KNN ranking function.
Dual Generative Answer Modes
Switch between Professor Oak (Coveo CRGA) for cloud-backed answers and any Ollama local model for fully offline inference. Model selector always visible in the top bar of both the dashboard and the coach.
Type & Generation Filters
Click type chips or generation rows in the sidebar to drive Coveo facets. Selecting a result automatically highlights the Pokémon's types and dims all others.
Habitat Map Card
After selecting a Pokémon, the sidebar map card shows all game encounter locations grouped by generation and region, with a live Serebii Pokéarth region image and PokéMaps deep-links where available.
Similar Pokémon Grid
Coveo's "More Like This" returns semantically similar Pokémon. Displayed as 3-column sprite cards below the search results. Click any to instantly pivot the entire dashboard.
Base Stats · Moves · Type Effectiveness
Rendered by the shared modules/pokemon-panel.js module — animated stat bars (HP/Atk/Def/SpA/SpD/Spe), a scrollable level-up moves table, and a type matchup grid. The same module draws the coach's comparison cards, namespaced per panel.

Professor Oak's Note
Nothing here answers from weights alone. The dashboard's agent loop in agent.py always retrieves real Pokémon data from the Coveo index before generating, and the coach sends every question — plus the recent conversation — through Coveo CRGA, which cites the documents it used. When CRGA declines to answer, the coach says so and falls back to the top search excerpts rather than inventing a reply. Then the grader checks the answer's type claims against the chart, and disagreements are shown to you, not swallowed.
Security: Coveo API keys are never exposed to the browser — /api/coveo-proxy and /api/rga-coveo inject the COVEO_ACCESS_TOKEN header server-side for every request, and /api/coveo-token returns only what Coveo Atomic needs to initialise its headless engine. The proxy's path is regex-anchored to /rest/search/v2* so a caller cannot steer a request to another host, CORS is scoped to this app's own origins rather than reflecting any origin, and coach sessions are capped at 20 turns and 1 000 sessions so the process cannot grow unboundedly.
